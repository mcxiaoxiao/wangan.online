##  DHCP欺骗 DHCP流程 :blue_circle:【重要】
### DHCP 四步握手流程

- **DHCP 发现**：客户端发送 `DHCP discover` 报文，源地址 `0.0.0.0`，目的地址 `255.255.255.255`（广播）
- **DHCP 提供**：服务器发送 `DHCP offer` 报文，包含提供的 IP 地址，目的地址为 `255.255.255.255`（广播）
- **DHCP 请求**：客户端发送 `DHCP request` 报文，确认选中的 IP，源地址 `0.0.0.0`，目的地址 `255.255.255.255`（广播）
- **DHCP 确认**：服务器发送 `DHCP ack` 报文，确认分配参数，目的地址为 `255.255.255.255`（广播）

!!! Warning "Tips"

    - DHCP 上述四个报文的目的地址全为 `255.255.255.255`，且均包含 `0.0.0.0` 这一 DHCP 特有的源地址特性
    - 默认网关（路由器）通常是子网网段的第一个 IP，例如 `/24` 网段的 `.1` 地址

### DHCP 欺骗原理

攻击者在网络中非法部署伪装的 **DHCP 服务器**，向请求 IP 配置的客户端分配精心设计的网络参数（如恶意网关地址、攻击者指定的 DNS 服务器地址）。

客户端接收并应用这些参数后，所有外部网络流量会被导向攻击者指定的恶意网关，所有 DNS 查询也会发往恶意 DNS 服务器，攻击者由此完全控制客户端的网络行为。

### DHCP 饥饿攻击（辅助攻击）

DHCP 饥饿攻击是一种辅助性攻击。攻击者通过伪造大量 **DHCP 请求**（使用不同 MAC 地址），**耗尽合法 DHCP 服务器的 IP 地址池资源**，使其无法再为合法客户端提供服务。

这为攻击者伪装成 DHCP 服务器上台创造了机会，迫使客户端不得不接受其分配的恶意配置。

### 攻击根本原因

**DHCP 缺乏身份认证机制**，客户端通常**无条件接受最先收到的 DHCP 提供响应**。攻击者的响应报文抢先到达客户端，从而成功欺骗客户端接受其分配的恶意配置。

!!! Warning "Tips"

    - DHCP 除了分配 IP 地址，还会分配子网掩码、默认网关、DNS 服务器地址等其他网络配置参数
    - DHCP 饥饿攻击与 MAC 地址攻击（MAC 冲刷）原理类似：都是通过耗尽资源（IP 池/转发表）来实现攻击或嗅探
    - MAC 攻击（MAC 冲刷）：用随机 MAC 地址耗尽交换机转发表，从而实现嗅探
