## 风暴型拒绝服务攻击（TCP SYN Flood、HTTP CC、IP 欺骗/Smurf） :pear:【重要】

### TCP SYN Flood 攻击
**TCP SYN Flood** 攻击的核心原理是：攻击者向目标服务器发送大量 **TCP SYN** 连接请求，但不回应服务器的 **SYN+ACK** 响应。

由于服务器不会收到最终的 **ACK** 包，它会一直等待，从而在服务器上建立大量 **半开连接**（或 SYN backlog 表），最终耗尽服务器的 **TCP 缓存**和连接资源，导致正常请求无法被处理，实现拒绝服务。

**防范手段**：

- 不再存储半开连接状态
- **SYN Cookies**：利用时间戳等信息生成加密 Cookie 来记录连接状态，而非为每个连接分配专属数据区，从而节省资源

!!! Warning "Tips"
    Linux 内核 ≥ 2.6 的发行版（CentOS ≥ 7、RHEL、Ubuntu、Debian）默认启用 SYN Cookies（`/proc/sys/net/ipv4/tcp_syncookies` 默认为 1）。
    其工作逻辑为：服务器收到 SYN 包并返回 SYN+ACK 时，不立即分配专属数据区，而是根据 SYN 包计算出一个 Cookie 值。等收到 ACK 包时，服务器验证该 Cookie 的合法性；若合法，再分配资源处理后续的 TCP 连接。

### IP 欺骗、Ping Floods 与 Smurf 攻击
#### IP 欺骗
**IP 欺骗**是指攻击者伪造一台主机的 **IP 地址**，冒充该主机与目标主机通信。其本质是破坏了基于 IP 地址的网络信任关系，常作为其他攻击（如 Smurf）的辅助手段。

#### Ping floods（ICMP 泛洪）
利用大量控制主机，向受害者发送海量 **ICMP ECHO** 请求（即 Ping 包）。这些数据包会大量占用受害者的网络带宽或系统资源，导致正常通信瘫痪。

#### Smurf 攻击
Smurf 攻击是一种典型的反射型 DoS 攻击。
攻击者向网络的 **广播地址** 发送一个 **ICMP ECHO** 请求，并将该包的 **源地址伪造为受害者的 IP 地址**。
网络中的所有设备都会收到此请求，并向受害者发送 **ICMP ECHO REPLY**（回显响应）包。
最终，受害者会收到来自大量主机的响应包，导致带宽被占满或系统资源耗尽而崩溃。

### HTTP CC 攻击
**HTTP CC**（HTTP Challenge Collapsar，代理攻击）攻击的核心是利用大量 **僵尸主机（Zombie）** 发起攻击。

攻击者控制大量僵尸主机，通过 HTTP 代理向受害者服务器发送大量 **合法的网页请求**。
受害者服务器会正常解析这些请求，但如果请求访问的是 **CPU 资源消耗极大** 的网页（如包含复杂逻辑的 PHP、ASP、JSP 页面），则大量僵尸主机的并发请求会迅速耗尽受害者服务器的 CPU 资源，导致服务瘫痪。
这种攻击的特点是：使用合法请求进行攻击，难以通过简单的防火墙规则进行拦截。
