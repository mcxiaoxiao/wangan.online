## 常见服务 中英文对照 端口 层 :strawberry:【重要·必考】

TCP（传输控制协议）（IP/协议字段**6**） 

UDP（用户数据报协议）（IP/协议字段**17**） 

RTP（实时传输协议 基于UDP）

IPv4（IP/版本字段**4**）头 20-60 字节 地址长 32 位 

IPv6（IP/版本字段**6**）头固定 40 字节 地址长 128 位 

MAC 地址长 48 位 

端口号 长 16 位


| 服务 | 端口/协议 | 层&备注 |
|-----|-----------|---------|
| <span style="color:#267B00">**文件传输协议 FTP 数据连接**</span> | <span style="color:#267B00">20/TCP</span> | 应用层<br>端口顺序可以这样记：FTP 写配置后 SSH 登录，登录了才能用 telnet 终端，再用 telnet 终端发 SMTP 邮件，邮件需要 DNS 找到域名的 IP |
| <span style="color:#267B00">**文件传输协议 FTP 控制连接**</span> | <span style="color:#267B00">21/TCP</span> | 应用层<br>FTP 会建立两个 TCP，一个 TCP 连接用于控制，另外一个 TCP 连接用来传输数据。（TCP 是双工的，这里因为功能不同不是上下行流量） |
| <span style="color:#267B00">**远程登录协议 SSH (Secure Shell)**</span> | <span style="color:#267B00">22/TCP</span> | 应用层 |
| <span style="color:#267B00">**终端仿真协议 Telnet**</span> | <span style="color:#267B00">23/TCP</span> | 应用层<br>未加密文本通信 |
| <span style="color:#C00000">**简单邮件传输协议 SMTP**</span> | <span style="color:#C00000">25/TCP</span> | 应用层<br>服务器间电子邮件传递<br>HELO<br>MAIL FROM<br>RCPT TO<br>DATA<br>QUIT<br>7 位 ASCII<br>CRLF CRLF 表明报文结束<br>MIME 是他的补丁，定义编码规则 |
| <span style="color:#C00000">**域名服务系统 DNS**</span> | <span style="color:#C00000">53/**TCP&UDP**</span> | 应用层<br>五个字段<br>**NAME** 名字<br>**CLASS** 类<br>**TYPE** 类型<br>**TTL** 生存时间<br>**RDATA** 真正的“数据”，格式随 TYPE 变化，Type 可以是：<br>A（IPv4）、AAAA（IPv6）、CNAME（别名）、MX（邮件交换）、NS（域名服务器）、TXT（文本）<br>UDP 协议进行域名解析<br>在区域传输中，DNS 强制使用 TCP 协议 |
| <span style="color:#267B00">**超文本传输协议 HTTP**</span> | <span style="color:#267B00">80/TCP</span> | 应用层<br>五类状态码<br>HTTP 方法：<br>GET(大小有限制，无 body 参数在 url 里，条件 get 用 if-no-modified)<br>HEAD（只要求部分内容）<br>DELETE<br>PUT<br>POST(无限制，参数在 body) |
| <span style="color:#267B00">**邮局协议第 3 版 POP3**</span> | <span style="color:#267B00">110/TCP</span> | 应用层<br>用于接收电子邮件 |
| <span style="color:#267B00">**交互邮件访问协议 IMAP**</span> | <span style="color:#267B00">220/TCP</span> | 应用层<br>POP3：下载→本地一份，服务器通常不保留。<br>IMAP：在线/离线都看服务器上的那份，客户端只是缓存，所有操作实时同步。 |
| <span style="color:#00438E">**动态主机配置协议 DHCP 服务器接收**</span> | <span style="color:#00438E">67/UDP</span> | 应用层<br>下面的 RIP，BGP 都是在应用实现，但是因为功能是网络层功能所以属于网络层。而 DHCP 并不实际参与网络层工作所以是应用层 |
| <span style="color:#00438E">**动态主机配置协议 DHCP 服务器发送**</span> | <span style="color:#00438E">68/UDP</span> | 应用层 |
| <span style="color:#00438E">**简单文件传输协议 TFTP**</span> | <span style="color:#00438E">69/UDP</span> | 应用层 |
| <span style="color:#00438E">**网络事件协议 NTP**</span> | <span style="color:#00438E">123/UDP</span> | 应用层 |
| <span style="color:#00438E">**简单网络管理协议 SNMP**</span> | <span style="color:#00438E">161/UDP</span> | 应用层 |
| <span style="color:#00438E">**简单网络管理协议 SNMP Trap**</span> | <span style="color:#00438E">162/UDP</span> | 应用层 |
| <span style="color:#00438E">**路由信息协议 RIP**</span> | <span style="color:#00438E">520/UDP</span> | <span style="background:yellow">应用层</span>实现的<span style="background:yellow">网络层</span>服务<br>距离向量路由算法 DV，BF, Bellman-Ford 周期性广播整张路由表，迭代更新<br>和 OSPF 可替代，但 RIP 适用于**小型同质**网络（15 跳限制、简单距离向量）；OSPF 面向**大型复杂网络**（链路状态、区域划分、快速收敛）。 |
| <span style="color:#267B00">**边界网关协议 BGP**</span> | <span style="color:#267B00">179/TCP</span> | <span style="background:yellow">应用层</span>实现的<span style="background:yellow">网络层</span>服务<br>路径向量路由算法<br>数字大炮（制造某些链路时断时续的震荡效应可以瘫痪所有路由）功能上看是“管路由”的，但实现上它跟 HTTP、SMTP 一样，都是跑在 TCP 之上的应用层程序。 |
| <span style="color:#A66500">**互联网控制消息协议 ICMP**</span> | <span style="color:#A66500">IP/协议**1**</span> | 网络层<br>分为 **差错报告 / 询问报文**<br>终点不可达<br>时间超过(Traceroute，是网络层工具)<br>参数问题<br>回送请求 type8 和回答 type0(PING，是应用层工具) |
| <span style="color:#A66500">**开放式最短路径优先 OSPF**</span> | <span style="color:#A66500">IP/协议**89**</span> | <span style="background:yellow">网络层</span><br>分布式链路状态路由算法, LS 本地跑 Dijkstra 算法<br>所有相邻路由器泛洪（flooding）发送，最终整个区域（Area）内的路由器都会收到同一份 LSA 副本(一台路由器的相邻链路状态信息) 报文大小和整个网络规模无关 支持认证和对 AS 分层<br>认证方式：NULL、简单口令、MD5 加密身份 |
| <span style="color:#7030A0">**地址解析协议 ARP**</span> | <span style="color:#7030A0">以太网帧</span> | 运行在链路和网络之间<br>在 OSI 算数据链路层<br>在 TCP/IP 算网络层（因为看到 IP 了） |

!!! Warning "Tips"
    端口是运输层（TCP/UDP）的复用/分用标识 ICMP（互联网控制消息协议） 直接工作在网络层（IP 之上），只负责主机↔主机之间的**控制与差错报文**（回显请求/应答、目的不可达、超时等）。这些报文由**内核网络栈**统一处理，不需要再细分到“进程端口”。所以不能用于端口扫描但可以用来主机扫描；
