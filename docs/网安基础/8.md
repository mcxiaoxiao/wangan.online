## 重定向拒绝服务攻击（ARP欺骗 中间人攻击）【重要】
ARP 地址解析协议属于**网络层**协议，核心功能是在局域网（LAN）内将目标主机的 **IP 地址** 解析为对应的 **MAC 地址**，以实现数据链路层通信。在共享网络中，攻击者获取主机 ROOT 权限并设置网卡混杂模式可实现窃听；在交换网络中，则主要通过 **ARP 欺骗** 实现流量劫持。

### ARP 欺骗原理
攻击者通过伪造 **IP 地址与 MAC 地址** 的映射关系（可使用 ARP 请求/响应报文），刷新目标主机的 **ARP 缓存表** 条目，使受害者将报文发往**错误的 MAC 地址**，从而劫持网络流量。

若同时修改通信双方的 ARP 缓存，则会形成 **中间人攻击**，攻击者可实现对流量的**嗅探、篡改或丢弃**（嗅探是中间人攻击的核心能力之一）。

### ARP 安全缺陷（根本原因）
- **无状态性**：主机收到 ARP 应答后会**无条件更新**本地 ARP 缓存，无需验证应答来源的合法性。
- **无认证机制**：ARP 协议本身不提供任何身份认证，攻击者可轻易伪造 ARP 报文。

!!! Warning "Tips"

    - **root 权限**：在 Linux/类 Unix 系统中，root 账户拥有最高权限，可对系统任意文件进行增删改查，甚至破坏整个系统，类似 Windows 的 Administrator 权限。
    - **混杂模式**：开启混杂模式需要 `CAP_NET_ADMIN` 能力（通常为 root），`libpcap` 在抓包时会自动将网卡设为混杂模式，因此“无 root 权限无法抓取他人流量”。
    - **ARP 欺骗实现**：依赖“将二层帧发送到网卡”，`raw socket` 是常见手段，但只要内核允许打开 `PF_PACKET` 并构造 ARP 报文，无需 `raw socket` 也可实现。
    - **中间人攻击严格定义**：攻击者必须同时冒充通信双方，污染双方 ARP 缓存，使流量双向经过攻击者，才能实现完整的截获与篡改；仅污染一方只能单向嗅探。
    - **攻击隐蔽性**：发送 ARP 应答比广播请求更隐蔽，不会产生大量广播流量，也不会触发 IP 冲突告警，是实际攻击中最常用的方式。

    ARP 缓存特性：

    - ARP 高速缓存存储在 **RAM** 中，**重启、掉电或系统重启** 会立即清空。
    - 默认超时时间：Windows 约 **2 分钟**，Linux 约 **60 秒**。
    - ARP 协议以**广播**方式工作，解析范围仅限**本地网络**，因此 **ARP 欺骗作用范围仅限于同一个广播域/本网段**。
