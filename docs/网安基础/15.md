## WEB脆弱性 网站攻击技术

### WEB 应用体系脆弱性

- 客户端（浏览器）漏洞
- Web 服务器漏洞
- Web 应用程序漏洞
- **HTTP 无状态性**：使攻击无需模拟会话，单个请求即可发起攻击
- **Cookie 包含敏感信息**
- 数据库可能保存攻击代码

### 主动攻击 vs 被动攻击

- **主动攻击**：直接攻击 WEB 服务器（如 **SQL 注入**），目的是篡改或破坏目标数据，会引发系统异常或故障。
- **被动攻击**：设置陷阱，用户浏览即感染（如 **CSRF、XSS、HTTP 消息注入**），目的是悄悄收集信息，对系统无明显破坏，难以发现。

!!! Warning "Tips"

    - 被动攻击：监听网络报文流，收集目标系统信息，不造成明显破坏，如网络窃听、爬虫、通信量分析。
    - 主动攻击：发送攻击报文，篡改或破坏目标数据，引发系统异常，如中断、重放、篡改、欺骗、控制、瘫痪、物理破坏。

### Cookie 脆弱性、欺骗 :pear:【重要】
Cookie 结构：

- `NAME=VALUE`
- `EXPIRE=DATE`
- `PATH=PATH`（URL 路径）
- `DOMAIN=DOMAIN_NAME`（对应域名，不指定更安全；指定易留隐患）
- `SECURE`（是否使用 SSL/TLS）

**Cookie 欺骗**：伪造 Cookie 信息绕过网站验证，因 Cookie 中保存了用户名、口令、权限等敏感信息。

**防范**：

- Cookie 仅存储会话 ID，数据本身存放在服务器端
- 或不使用 Cookie，改用 **Token 令牌机制**（如 JWT）

!!! Warning "Tips"

    - Token-Based Authentication 机制，如 **JSON Web Token (JWT)**。
    - 会话变量可使用 Redis、Memcached 等在服务器端存储 Session。

### SQL 注入攻击 :pear:【重要】

将精心构造的 SQL 命令插入表单、域名或页面请求的查询字符串中，欺骗服务器执行 SQL，实现：

- 非法访问数据库内容
- 篡改数据
- 绕过认证
- 运行程序、编辑文件

**防范**：

- 对用户输入进行检查（转换或过滤单引号、双引号、分号等特殊字符）
- 遵循**最小特权原则**
- 不使用动态拼装 SQL，使用**参数化 SQL**
- 尽量减少返回的错误提示信息

### XSS 跨站脚本攻击 :pear:【重要】
将恶意代码（HTML 和客户端脚本）注入到其他用户浏览器显示的页面中，以受害者身份执行。

**两个前提**：

1.  Web 程序必须接受用户输入（包括 URL 参数、表单字段、HTTP 头部、Cookie 值）

2.  Web 程序会重新显示输入内容，且浏览器将其解释为 HTML 标记

**形式**：

- **反射式（URL）**：构造恶意 URL，受害者访问时执行其中的恶意代码
- **储存式（持久性）**：恶意数据存储在服务端，被显示给受害者时执行
- **DOM 式**：修改页面 DOM 结点数据

**防范**：

- 对用户输入的所有内容进行过滤或编码
- 对输入的 HTML 内容做白名单检查

---

### CSRF 跨站请求伪造 :pear:【重要】
攻击者伪装成受信任用户发送恶意请求。
用户在未清理 Cookie 的情况下访问恶意网站，恶意网站会携带用户的 Cookie 发送恶意请求。

**防范**：

- 使用一次性令牌并保证 Token 安全
- 要求用户重新输入密码
- 检查 HTTP `Referer` 头

!!! Warning "Tips"
    - `Referer` 用于携带请求来源地址，常用于反爬虫和防盗链，HTTP 标准将其拼写为 `referer`（少一个 r）。

---

### 目录遍历 :pear:【重要】
**条件**：

1.  允许外界指定文件名
2.  允许使用绝对/相对路径指定其他目录的文件名
3.  未对拼接后的文件名进行校验即允许访问

**防范**：

- 避免外界指定文件名
- 文件名不包含目录路径
- 限制文件名仅包含字母和数字

---

### 操作系统命令注入 :pear:【重要】
**原因**：应用程序调用 Shell，而 Shell 允许连续执行多条命令。

**防范**：

- 不调用 Shell
- 外部输入字符串不能作为命令行参数
- 对特殊字符进行转义

!!! Warning "Tips"

    - 命令注入是 Web 漏洞，攻击者将系统命令拼入输入，让服务器执行恶意命令（如 ` rm -rf /`）。
    - ROP 是二进制漏洞利用技术，用于劫持程序控制流，属于内存攻击。

---

### HTTP 消息头注入 :pear:【重要】
基于外部参数生成 HTTP 响应头时产生的安全问题，可通过**换行**插入任意响应头或消息体，实现：

- 生成任意 Cookie
- 重定向到任意 URL
- 执行 JS 代码，实现 XSS 效果

**防范**：

- 不将外部参数直接作为 HTTP 响应头输出
- 使用会话变量转交 URL，由专门 API 处理重定向或生成 Cookie
- 严格检查 HTTP 头中的换行符
- 不使用 URL 直接指向重定向目标

!!! Warning "Tips"
    - 会话变量可使用 Redis、Memcached 等在服务器端存储 Session。
